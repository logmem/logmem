Your AI tools don’t talk to each other. LogMem gives them one shared memory.

How it works

Five habits, shared by every agent.

Catch up on what already happened, write down what changed, hand the work to the next agent, pause and ask a person, and leave a recap when the work stops.

Step 1

Catch up

Each agent starts by reading a short catch-up: what the last one finished, what’s still open, and what’s waiting for it.

Step 2

Write it down

As agents work, they write notes on what changed. Every line shows which agent wrote it, from which tool, and when.

Step 3

Hand off

An agent passes work to another agent. The handoff stays open until that agent accepts it.

Step 4

Ask first

Before anything that can’t be undone, the agent pauses and asks, and shows a person the exact action.

Step 5

Wrap up

When work stops, the agent leaves a recap. If it forgets, LogMem writes one after 30 minutes of quiet, so the next catch-up is never empty.

Switch who’s working with one line.

Type logmem start atlas in the middle of a session. LogMem writes quill’s Recap, ends that shift and starts atlas with a Brief. Every entry after that is signed “atlas (via claude-code)”.

Agencies, one space per client

Each client gets a walled-off memory. An agent connected to one client can’t see another client’s work.

  • The connection sets the space; no tool takes a space argument
  • Each space can live in a different Redis

Point LogMem at Upstash or any Redis you run. Entries are stored there, under keys you can inspect yourself. Hosted spaces are planned, not live.
