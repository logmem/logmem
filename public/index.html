How it works

A few plain words, used the same way by every agent.

LogMem is an MCP server. Agents call its tools; people read the result. If an agent forgets a habit, LogMem keeps it for them.

Beginning of a shift

Start, then Brief

The agent becomes who it is and reads its last Recap, what it was doing, recent entries and any handoffs waiting for it. If it skips this, its first call starts the shift anyway.

logmem_start agent: "quill"
During the work

Note, Handoff, Ask

Notes record what changed. A Handoff passes work to another agent and stays open until they accept it. Ask stops the agent and shows a person the exact action before anything irreversible runs.

logmem_handoff to: "atlas"
End of a shift

Recap

The agent leaves notes and next steps for whoever comes next. Idle for 30 minutes? LogMem writes the Recap itself, so the next Brief is never empty.

logmem_recap notes: "…"

Switch who’s working with one line.

Type logmem start atlas in the middle of a session. LogMem writes quill’s Recap, ends that shift and starts atlas with a Brief. Every entry after that is signed “atlas (via claude-code)”.

QUquill
recap → start
ATatlas

Solo builder, several agents

Claude Code in one terminal, Codex in another, Cursor in the editor. They share one log, so each knows what the others did and you stop pasting context between them.

  • Switch persona mid-session with logmem start
  • Every entry says which host wrote it
RE Pending decision NO

Small team with a human approver

Agents do the work. One person approves the steps that can’t be taken back: sending, paying, deleting, publishing. They see the exact action and who asked for it.

  • Approved and completed are tracked separately
  • Rejections and deferrals stay on the record
acmebirchcorvo

Agency with one space per client

Give each client its own space. An agent connected to one space can’t read another, so one client’s memory never shows up in another client’s work.

  • The connection sets the space; no tool takes a space argument
  • Each space can live in a different Redis
Trust

Your data, with a name on every line.

Your Redis

Point LogMem at Upstash or any Redis you run. Entries are stored there, under keys you can inspect yourself. Hosted spaces are planned, not live.

Every write attributed

Each entry records who wrote it, through which host, and when, to the millisecond.

Approvals before irreversible actions

An agent asks before anything it can’t undo, then waits for an entry that records the decision. In v0 the agent honours the wait; server-side enforcement is planned.

A read-only web app

The app shows the log, jobs and pending decisions. It can’t edit or delete entries, so what you see is what the agents wrote.

Built on ACMI

An open protocol underneath.

LogMem implements ACMI, the MIT-licensed Agentic Context Memory Interface, and passes its conformance suite. Agents that already speak ACMI keep working: compatibility mode reads their history and accepts their calls.
