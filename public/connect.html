Setup

Connect your AI to LogMem.

Three steps, about five minutes. First you add one link to your AI. Then you paste one message. Your AI checks the connection, reads your shared Brief, and asks what to work on.

Hosted plans: join the waitlist. Managed hosted access is invite only unless you already received an invite or a teammate’s workspace invitation link. No invite yet? Request access to join the waitlist, or self-host on your own Redis with no invite needed.

1 Pick your AI

2 Copy this link

https://logmem.si/mcp

Use this exact link. Do not shorten it to logmem.si. Then follow the clicks or commands for your AI below.

3 Add it, verify, then paste your message

Claude: add the link

  1. Open claude.ai. Click your name, then Settings, then Connectors.
  2. Click Add custom connector.
  3. Type LogMem as the name. Paste https://logmem.si/mcp from the box above. Click Add.
  4. Click Connect next to LogMem. A LogMem sign-in page opens.
  5. Sign in with your invited email (or workspace account). Pick your space. Click Allow.

Menu names change now and then. Look for Connectors. Some work or team plans need an owner to allow custom connectors.

On the Claude phone app? Add the connector on claude.ai in a browser first, with the same account. Then open the app, start a chat, tap +, then Connectors, and switch LogMem on. The app cannot always add a new connector itself.

Check it works. Start a new chat with LogMem switched on and run logmem_connection (send: Run logmem_connection and show me ok, space, and degraded.). Confirm it returns ok: true, your expected space, and degraded: false. If Claude says it has no LogMem tools, switch LogMem on for that chat or connect again.

Gemini CLI: add the link

  1. Add the hosted MCP server from your terminal: 
    gemini mcp add -s user --transport http logmem https://logmem.si/mcp
    Or edit ~/.gemini/settings.json (or .gemini/settings.json for one project) and add logmem under mcpServers with httpUrl: 
    {
  "mcpServers": {
    "logmem": {
      "httpUrl": "https://logmem.si/mcp"
    }
  }
}
  2. Run gemini mcp list in your terminal, or start gemini and run /mcp (or /mcp list) to confirm logmem is listed.
  3. Inside gemini, run /mcp auth logmem to open sign-in in your browser. Sign in with your invited email (or workspace account), pick your space, and click Allow.

Gemini CLI uses httpUrl in ~/.gemini/settings.json for Streamable HTTP (url is for legacy SSE). On a Gemini web or mobile app, check your version’s custom MCP connector settings; if it lacks custom MCP, use Gemini CLI or self-host via Bring your own Redis.

Check it works. Start a session and run logmem_connection (send: Run logmem_connection and show me ok, space, and degraded.). Confirm it returns ok: true, your expected space, and degraded: false.

Codex CLI & app: add the link

  1. Add LogMem from your terminal and start OAuth sign-in: 
    codex mcp add logmem --url https://logmem.si/mcp
codex mcp login logmem
    Or edit ~/.codex/config.toml directly (or .codex/config.toml in your project) and add [mcp_servers.logmem], then run codex mcp login logmem: 
    [mcp_servers.logmem]
url = "https://logmem.si/mcp"
  2. In the browser window that opens, sign in with your invited email (or workspace account), pick your space, and click Allow.
  3. In the Codex app, you can also open Settings → MCP Servers and add logmem with https://logmem.si/mcp. Run codex mcp list (or /mcp in Codex) to confirm logmem is connected.

Running local @logmem/mcp with your own Redis instead? Use Bring your own Redis to generate the [mcp_servers.logmem] stdio TOML block with your LOGMEM_SPACE and LOGMEM_AGENT.

Check it works. Start a Codex session and run logmem_connection (send: Run logmem_connection and show me ok, space, and degraded.). Confirm it returns ok: true, your expected space, and degraded: false.

How you know it worked

Run logmem_connection in your AI and check that it returns ok: true, the space you expect, and degraded: false. Then your AI reads its Brief and asks which business or project to work on. From then on it writes its progress into your shared space.

Stuck?

  • “No MCP server was found.” The link is wrong. Use https://logmem.si/mcp exactly, with /mcp at the end.
  • “Authentication required.” The sign-in did not finish. Click Connect again (or run /mcp auth logmem in Gemini CLI / codex mcp login logmem in Codex) and finish the sign-in page.
  • The sign-in puts you on the waitlist (not invited). Managed workspaces require an invite or a teammate’s invitation link. Request access and wait for our email, or run your own Redis with @logmem/mcp right now.
  • You do not see Add custom connector. Your plan or your workspace owner may block it. Ask the owner to allow custom connectors.

You stay in control

  • You approve every connection. Nothing joins your space until you click Allow.
  • Agents ask before anything that cannot be undone. Sending, spending, deleting and publishing wait for a person. The message above says so.
  • Private stays private. Agents keep private information out of shared work unless you approve sharing it.
  • Pause anyone, any time. A paused agent stops until you say otherwise.

Other ways in

  • Self-host (no invite needed): The core is MIT open source. Run npx -y @logmem/mcp on your own Redis or HTTP bridge. Follow Bring your own Redis or read the docs.
  • Hosted (invite only): Managed workspaces require an invite or a teammate’s invitation link. Request access / join the waitlist →
