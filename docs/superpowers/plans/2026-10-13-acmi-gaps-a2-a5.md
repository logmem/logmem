## A4 — windowed compat reads without full scans

**Problem.** `readLog` in compat mode runs `ZRANGE legacy 0 -1` on every call because legacy scores mix ms, µs,
s and ns, so a score-range query would miss entries. On `thread:agent-coordination` (1,400+ entries, growing
hourly from Muse's drive loop) every Brief, Feed and View pulls the whole key. That response size is the same
failure class as ACMI's `acmi_cat` REST 500s.

**Fix: query each unit band, not the whole key.** For a window `[min, max]` in ms, the legacy entries that
belong in it are exactly the members whose raw score falls in one of these bands:

| Unit | Raw score band |
|---|---|
| ms | `[min, max]` |
| s | `[min/1e3, max/1e3]` (only where the result is ≥ 1e9) |
| µs | `[min*1e3, max*1e3]` |
| ns | `[min*1e6, max*1e6]` |

Four `ZRANGEBYSCORE … WITHSCORES` calls (pipelined where the backend supports it) replace one full `ZRANGE`.
They return the same rows `normTs` would have kept, with no scan.

- **"Last N" reads (Brief, recent)**: `ZREVRANGEBYSCORE … LIMIT 0 N` per band, merge after `normTs`, then
  take N. This is correct because each band is internally ordered.
- **Non-ZSET legacy timelines** (string/list, now readable after PR #27): these are small (largest in the dry run: 17
  items), so keep the in-memory filter for them.
- **lm keys**: already in ms. Add `LIMIT` to `ZRANGEBYSCORE`/`ZREVRANGEBYSCORE` so Briefs stop loading whole
  logs too (the lm half of GAPS U8).
- **Precision**: ns band bounds above 2^53 lose precision as JS numbers. Widen the band by ±1e3 and let the
  post-`normTs` filter drop the edges.

**Tests.** Seed one key with entries in all four units around a window edge. Assert that the banded read
equals the old full-scan read for: since-only, until-only, both, last-N, reverse. Add a key with 5,000 entries
and assert the read issues no `ZRANGE 0 -1` (spy on the runner).

**Done when** compat `readLog`/`logSize`/`logmem_feed` never full-scan a ZSET, the tests above pass, and
conformance stays 30/30.

## A3 — stage index for jobs

**Problem.** `logmem_jobs` must know every job's stage to hide `done`. PR #27 batches the reads (25 at a
time), but that is still about 1,400 Redis calls for 704 jobs in compat mode.

**Fix.**
1. **Index on write.** When `setNow("job", id, {stage})` changes the stage, `SREM` the old
   `lm:{space}:job:stage:{old}` and `SADD` the new one. This is done in the same call path as the HSET; the
   atomic version comes with GAPS D2 (Lua).
2. **Read path.** `logmem_jobs` reads `SMEMBERS lm:{space}:job:stage:done` once. Jobs not in any stage set
   fall back to the batched `getNow` (legacy-only jobs before the copy).
3. **Backfill.** The migration copy (A5/A2 PR) writes `stage` into each copied job's `now`, using
   `STAGE_FROM_STATUS`, and builds the four stage sets. After the copy, the fallback set is empty.
4. **Repair.** Add `scripts/reindex-stages.mjs` (dry-run by default) that rebuilds the sets from `now` for
   drift recovery.

**Tests.** Stage transitions move ids between sets. `logmem_jobs` hits the index (spy) and agrees with the
batched path on a mixed fixture. The reindex dry run reports drift without writing.

**Done when** `logmem_jobs` on an indexed space makes O(1) stage reads, and the index survives every stage
transition in the existing stage tests.

## A5 — near-1970 scores, and stopping bad timestamps at the source

**Two problems, one root cause.**
- (a) 88 legacy entries have scores < 1e9. They sort as 1970 and fall out of every window.
- (b) Writers are **still** producing bad timestamps. Muse's drive-loop event on 2026-10-12 has
  `ts: 1791853034186350600` (ns). ISO strings appear as `timestamp` fields. Each new bad write re-creates the
  A5/A4 problem.

**Fix (a): classify, then rescore on copy.**
1. Extend the dry run (read-only) to list all 88 with key, raw score, and any `ts`/`timestamp` in the member.
   Classify each one:
   - **Recoverable**: the member carries a real time (`ts` ≥ 1e9 in any unit, or an ISO string, which
     `normTs` now parses). Copy it scored by that time.
   - **Fixture**: on test keys (`TestUser`, `--action`, …). Exclude them, matching the junk-namespace rule in
     PLAN.md.
   - **Unrecoverable**: no usable time. Copy it scored at the key's earliest real entry minus 1 ms, with
     `ts_recovered: false`, so it stays near its siblings rather than 1970. Report each one.
2. The rule is applied in the copy step and recorded in the `--verify` report: count per class, zero entries
   < 1e9 in `lm:*`.

**Fix (b): validate at write.**
- LogMem already normalises on write (PR #27 adds ISO). Nothing more is needed server-side.
- For writers still on raw ACMI before cutover: post a `coord-note` to each writer seen emitting non-ms
  scores (from the dry-run `score_units` by source; Muse first), with the one-line fix
  `ts: Date.now()`. `thread:agent-coordination`, where Muse posts its drive-loop events, holds 46 of the 74 non-ms entries the dry run rescored.
- Add a `--watch-units` mode to the dry run that reports new non-ms entries since a timestamp, so the fleet
  can see the count trend to 0 before cutover.

**Decision needed (Mikey).** Approve the three-class rule above. The alternative is to drop unrecoverable
entries, which loses history. The recommendation is to keep them with the flag.

## A2 — the 1,108 `id-has-colon` keys

**Problem.** `planKey` refuses any key whose id contains `:`. After cutover those keys are invisible through
`logmem_*`, and compat reads can't reach them either, because `parseRef` and `lmKey` reject the extra segment.
The examples are not all one thing:

| Pattern (from dry-run examples) | What it is | Proposed mapping |
|---|---|---|
| `agent:agent:bentley:timeline`, `agent:agent:fleet-architect:rollup:latest` | ACMI CLI namespace footgun (double prefix) | **Collapse** to `agent:bentley`. Merge into the existing log, deduping by `ts`+`trail`+`summary` (the same signature compat reads use). |
| `agent:antigravity:ops-center-amd-agents:timeline` | An agent's sub-thread | **Dot-join** to `channel:antigravity.ops-center-amd-agents`. Record `origin_key` in `who`. |
| `agent:avery:install-hygiene-ack-required:timeline` | Per-agent ack thread | Dot-join as above. |
| `agent:bentley-main:rollup:latest:profile` | Malformed slot nesting | **Exclude** and report. Junk, no readers. |

**Steps.**
1. **Classify (read-only, claude-engineer, needs bridge).** Extend the dry run to bucket all 1,108 keys by
   pattern: double-prefix, sub-thread, malformed-slot, other. Report counts plus 10 examples each. Nothing
   ships until the "other" bucket is small and reviewed.
2. **Decide (Mikey).** PLAN.md O2 already proposes collapse + dot-join. Approve the table above or amend it.
3. **Implement in `planKey`.** Add the collapse and dot-join rules with a `rule` field on each plan row. The
   copy writes the `lm:` target and records `origin_key` (who) / `origin_key` per entry, so it is traceable
   back to ACMI. Dot-joined ids must pass `validateKeySegments` (no `:`). Any that fail go to "other".
4. **Compat read bridge.** Until the copy runs, add a small alias map (built by the classifier, stored at
   `lm:{space}:registry:aliases`, protected) so compat reads of `agent:bentley` also read
   `acmi:{space}:agent:agent:bentley:timeline`. That makes Bentley's old history visible before cutover.
   This one is optional; skip it if the copy is close.
5. **Verify.** The `--verify` report counts every one of the 1,108 keys as mapped, merged, excluded or
   other, with zero silent drops.

**Tests.** `planKey` unit tests for each pattern. Merge dedupe on a double-prefix fixture that overlaps the
real key. Dot-join ids validate. Malformed keys are excluded with a reason.
