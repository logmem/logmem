# acmi-bridge: per-tenant Redis ACL user (defence in depth under the bridge jail).
#
# Provisioned by slice D (`acmi-cloud tenant create` / `acmi-cloud bridge render`),
# never by hand and never committed rendered. The provisioner:
#   1. generates a random password, stores it in Infisical, and renders
#      {{PASSWORD_SHA256}} as its sha256 (hex): Redis keeps only the hash;
#   2. loads this rule with an admin connection (ACL SETUSER, or an aclfile
#      plus ACL LOAD), then ACL SAVE when an aclfile is in use;
#   3. loads the meter reserve script once (SCRIPT LOAD, admin connection), so
#      the bridge can call it with EVALSHA. Repeat after every Redis restart or
#      SCRIPT FLUSH: until it is loaded, writes on refusing plans fail closed
#      (503) and a starting bridge refuses to start;
#   4. sets ACMI_REDIS_URL_{TENANT_ENV}=redis://acmi-t-{tenant}:<password>@redis:6379
#      in Infisical for the compose service.
#
# What the rule allows:
#   keys      only acmi:t-{tenant}:*, lm:t-{tenant}:* and the tenant's own meter
#             counters acmi:cloud:meter:{tenant}:* (scripts are held to the same
#             patterns: Redis checks the keys a script declares)
#   channels  none
#   commands  exactly the bridge command table (cloud/bridge/bridge.mjs COMMANDS)
#             plus EVALSHA for the meter reserve script. No @dangerous, @admin or
#             @scripting categories, no EVAL, SCRIPT, FUNCTION, KEYS, FLUSH*,
#             CONFIG, CLIENT, DEBUG, SORT, SELECT or MIGRATE.
#   caveat    SCAN takes no key argument, so the ACL cannot narrow it; the bridge
#             forces its MATCH to the tenant prefix. A jail bypass could list
#             other key names (not read them) through SCAN.
#
# Placeholders: {{TENANT}} tenant id; {{PASSWORD_SHA256}} sha256 hex of the password.
