# acmi-bridge: per-tenant Redis ACL users (defence in depth under the bridge jail).
#
# Two users per tenant, on two separate connections:
#   acmi-t-{tenant}      tenant data. Used for every tenant command (ACMI_REDIS_URL).
#   acmi-meter-{tenant}  that tenant's usage counters. Used only by the meter
#                        (ACMI_METER_REDIS_URL). The tenant user has no access to
#                        them, so even a jail bypass cannot rewrite its own usage.
#
# Provisioned by slice D (`acmi-cloud tenant create` / `acmi-cloud bridge render`),
# never by hand and never committed rendered. The provisioner:
#   1. generates two random passwords, stores them in Infisical, and renders
#      {{PASSWORD_SHA256}} / {{METER_PASSWORD_SHA256}} as their sha256 (hex):
#      Redis keeps only the hashes;
#   2. applies each rule with an admin connection:
#        ACL SETUSER <name> <the rule below, from "reset" on>
#      (or an aclfile + ACL LOAD, then ACL SAVE). Each rule starts with
#      `reset`, so re-applying it (a password rotation, a template change)
#      REPLACES the user: old password hashes, key patterns, commands and
#      selectors are gone, not merged;
#   3. loads the meter reserve script once (SCRIPT LOAD, admin connection), so
#      the meter user can call it with EVALSHA. Repeat after every Redis restart
#      or SCRIPT FLUSH: until it is loaded, writes on refusing plans fail closed
#      (503) and a starting bridge refuses to start;
#   4. sets, in Infisical, for the compose service:
#        ACMI_REDIS_URL_{TENANT_ENV}=redis://acmi-t-{tenant}:<password>@redis:6379
#        ACMI_METER_REDIS_URL_{TENANT_ENV}=redis://acmi-meter-{tenant}:<password>@redis:6379
#
# Tenant user:
#   keys      only acmi:t-{tenant}:* and lm:t-{tenant}:*
#   channels  none
#   commands  exactly the bridge command table (cloud/bridge/bridge.mjs COMMANDS).
#             No EVAL/EVALSHA, no @dangerous, @admin or @scripting categories,
#             no SCRIPT, FUNCTION, KEYS, FLUSH*, CONFIG, CLIENT, DEBUG, SORT,
#             SELECT or MIGRATE. (SELECT not granted: use database 0.)
#   caveat    SCAN takes no key argument, so the ACL cannot narrow it; the bridge
#             forces its MATCH to the tenant prefix. A jail bypass could list
#             other key names (not read them) through SCAN. COPY ... DB n cannot
#             be limited by key patterns; the jail refuses the DB option.
#
# Meter user:
#   keys      only acmi:cloud:meter:{tenant}:* (Redis also checks the keys a
#             script declares, so the reserve script is held to the same pattern)
#   commands  PING, GET (quota reads), INCRBY (count and refund), EXPIRE (TTL),
#             EVALSHA (the reserve script). No EVAL, so an unloaded script fails
#             closed instead of running caller-supplied Lua.
#
# Placeholders: {{TENANT}} tenant id; {{PASSWORD_SHA256}} / {{METER_PASSWORD_SHA256}}
# sha256 hex of each password.
